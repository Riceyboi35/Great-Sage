# Lesson summary

Write for Dan to read on his phone in a couple of minutes.

## Steps
1. List what changed since the last summary (check git log, changed files, and
   any notes in `work-log.md` if it exists).
2. For each change, write:
   - **What I did** — one sentence.
   - **Why** — one sentence.
   - **What you'd learn from this** — one or two sentences explaining the idea
     in plain language, as if teaching him.
   - **Needs your OK?** — yes/no, and what exactly to approve.
3. Finish with:
   - **Am I on track?** — honest take.
   - **One thing worth adding** — a single side recommendation.
   - **Next up** — what you'll do next if he approves.
4. Append a dated one-line entry per change to `work-log.md` so there's a record.

## Rules
- Plain Australian English, no jargon without a quick explanation.
- Keep it under one phone screen per change.
- Never mark something as done if it isn't working.
